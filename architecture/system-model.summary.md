# 净源智研 · 当前状态架构说明

> 一句话：这是一个可离线演示的毕业设计原型——每日从模拟源取监测数据，经规则、AI 与风险模型形成线索和事件，由审核人员下发核查任务，现场人员在 H5 / Android 上取证反馈并闭环。

## 1. 系统边界

当前原型由三端一库组成：

- **Web PC 端**：Vue 3 SPA，覆盖监管大屏、企业台账与画像、事件工作台、任务、采集、监测、质量、规则、回测、报告与数据共享页面。
- **移动 H5**：与 PC 共用同一 Vue 构建产物的 `/m/tasks` 路由，免安装。
- **Android 原生端**：Kotlin + Material 3，OkHttp 直连 `/api/mobile/*`，支持相机水印、定位、附件上传和弱缓存。
- **数据层**：Spring Boot 后端 + H2 文件库（25 张表）+ 本地 `/app/uploads` 目录。

部署形态是 Docker Compose 单机：

- `frontend`：Nginx 1.27，8088 端口，托管 SPA 与 APK，反向代理 API。
- `backend`：Spring Boot 3.2.0，8080 端口，JRE 21 运行，Java 17 源码。
- 两个 named volume：`fixed-source-data`、`fixed-source-uploads`。

## 2. 逻辑视图

### 2.1 角色与外部系统

| 角色 | 主要动作 |
|---|---|
| 监测分析人员 `analyst` | 看画像/证据/趋势，发起 AI 研判，手工标记线索；台账只读 |
| 审核人员 `reviewer` | 确认/撤销线索，拆分合并事件，创建下发督办关闭任务，维护台账 |
| 现场核查人员 `inspector` | H5/Android 接单、拍照水印、附件上传、反馈 |
| 系统管理员 `admin` | 规则、数据源、台账维护；拥有全部角色权限 |

外部系统（本原型中均为同进程模拟）：

- **模拟监测数据源**：`/mock-source/v1`，10 家企业、20 个点位、6 类污染物，内置异常剧本。
- **国家数据共享平台**：目录、打包、订阅、HMAC 投递、回执、开放拉取；5 个模拟订阅方（npe / enf / city / open / edge）。
- **公开法规知识库**：`knowledge/regulations.json`，10 条法规片段，供 mock-rag 检索。

### 2.2 后端模块

后端是单体 Spring Boot，业务模块、模拟源、数据共享模块和 Mock 接收端在同一 JVM：

- 认证与会话：X-Token / Bearer，UUID token 存内存 Map。
- 采集接入：批次 + HTTP 拉取 + MERGE 幂等 + 失败回退进程内生成器。
- 数据质量：缺失/异常留痕，按 24 个应到小时计算每日完整率。
- 规则引擎：R001 浓度超限、R002 数据缺失、R003 连续恒值、R004 异常突变、R005 状态不一致；证据快照 + fingerprint 去重。
- 事件与风险：同企业/排口/污染物/相邻时段聚合为事件，P1–P3；企业风险 A/B/C/D。
- AI 辅助研判：mock-rag-v1，按 ruleCode + pollutant 检索；命中引用，未命中拒答。
- 任务闭环：确认线索 → 任务 → dispatch_outbox → 移动端轮询 → 接收 → 拍照/反馈 → 关闭。
- 台账/画像/大屏：企业、点位、监测分析、区域/行业态势、离线北京 GeoJSON。
- 回测/报告/测试数据：规则回测、可打印报告、异常真值标签与 CSV。
- 基础数据服务出口：7 类数据集，只共享基础数据域，不共享规则、事件、风险、AI 与任务。
- 数据共享平台模块：data_catalog / subscriber / package / dispatch / receipt，HMAC-SHA256 投递与回执。

### 2.3 数据域

25 张 H2 表分为 6 个域：

| 数据域 | 表数 | 关键内容 |
|---|---:|---|
| 基础主数据 | 4 | 企业、点位、污染物标准、公开名录 |
| 监测与采集 | 4 | 逐小时监测记录、批次、质量问题、数据源配置 |
| 规则与线索 | 4 | 规则配置、线索、真值标签、回测记录 |
| 事件·风险·研判 | 3 | 事件、风险快照、AI 研判 |
| 任务与报告 | 5 | 任务、反馈、报告、下发 outbox、审计 |
| 数据共享 | 5 | 目录、订阅方、数据包、投递、回执 |

## 3. 端到端闭环

### 3.1 监测研判与任务闭环

1. **模拟源出数**：按业务日期生成逐小时监测记录，含超限、恒值、突变、状态不一致等异常剧本。
2. **采集批次入库**：创建批次，HTTP 拉取并 MERGE 写入 `monitoring_record`，重复采集幂等。
3. **质量校验**：记录缺失/异常，计算每日完整率。
4. **规则生成线索**：R001–R005 生成 `clue`，保存触发值、阈值、时间范围、证据与 fingerprint。
5. **AI 辅助研判**：检索 10 条法规片段；命中输出解释、引用、建议与置信度；未命中拒答并降低可信度。
6. **事件聚合与风险**：聚合事件，定 P1–P3；按 7 日事件、完整率与待办任务计算企业 A/B/C/D。
7. **审核下发**：确认线索，创建任务，写 `dispatch_outbox` 并置 `DISPATCHED`；可督办/重试对账。
8. **现场闭环**：H5/Android 轮询任务，接收后拍照并叠加时间、地点、企业、点位水印，上传附件，提交反馈；审核关闭后事件状态回写。

### 3.2 基础数据共享闭环

1. **基础数据服务出口**：数据平台用 `datahub` 服务账号获取 7 类基础数据。
2. **封装数据包**：header + body，计算 SHA-256 payload hash，写 `data_package`。
3. **HMAC 投递**：用订阅方 secret 计算 `HMAC-SHA256(timestamp + packageNo + sha256(body))`，POST 到接收端。
4. **验签与幂等**：校验 AppKey、10 分钟时间窗、签名；按 packageNo 幂等，写 `data_receipt`。
5. **对账与重试**：记录 HTTP 状态、延迟、签名与响应；失败重试；包状态 PUBLISHED / DISTRIBUTED / PARTIAL / FAILED。
6. **开放拉取**：独立 `X-Open-Data-Key` 访问 catalog 与 latest，与业务 token 分离。

## 4. 关键设计取舍

- **单体 + H2 + Docker Compose**：以离线可复现为第一目标，牺牲了水平扩展、独立部署和高可用。
- **模拟源与数据平台同进程**：用真实 HTTP + 服务账号 + HMAC 模拟跨平台对接，逻辑边界清晰，但物理上不是独立服务。
- **outbox + 移动端轮询**：任务下发是 outbox 记录与状态变更，没有推送网关或消息队列；移动端通过轮询拉取。
- **确定性 mock RAG**：不依赖外部模型/网络，保留引用、拒答与人工复核边界；置信度是确定性公式，不代表真实模型效果。
- **内存会话**：实现简单，但服务重启会使 token 全部失效；没有刷新 token、设备绑定或集中式会话。
- **风险分只由规则、事件与反馈计算**：台账维护写审计日志，不允许直接改分。

## 5. 已知边界（答辩时建议主动说明）

1. **采集不是定时触发**：README 说“每日采集”，但代码中只发现 `@EnableScheduling`，没有 `@Scheduled` 任务；当前由 `POST /api/collect-batches` 或页面按钮触发。若答辩需要“每日自动采集”，需要补调度器。
2. **数据共享平台不是独立部署单元**：同 JVM、共用 H2；没有独立服务、消息队列或对象存储。
3. **任务下发没有推送网关**：outbox + 轮询，不是可靠消息投递。
4. **会话不持久化**：token 存内存，重启失效。
5. **AI 是确定性 mock RAG**：10 条法规片段，置信度公式化，不代表真实大模型能力。
6. **Android 运行验收待补**：源码与 Debug APK 完成，但当前环境无模拟器/真机，相机、定位与 UI 运行验收需真机补测。
7. **单节点存储与明文链路**：H2 单文件、本地上传目录、HTTP 明文、局域网演示；生产化需要 HTTPS、备份、对象存储、Token 刷新和更细权限。

## 6. 交付物与打开方式

- `system-architecture.html`：单文件离线交互图，双击即可打开；支持缩放、拖拽、点击节点/连线查看职责、协议与证据，支持导出当前视图 SVG 与打印。
- `system-model.json`：当前状态架构模型，包含节点、关系、坐标、置信度、`sourceRefs`、流程与数据口径；是唯一源。
- `system-model.evidence.md`：证据索引，按 L1/L2/关系/闭环/数据/边界组织。
- `system-model.summary.md`：本文件，面向答辩与交接的架构说明。
- `build/`：可选的再生成脚本。修改 `system-model.json` 后执行 `node architecture/build/build.mjs`，会重新生成 `system-architecture.html`；日常查看不需要构建。

## 7. 如果继续演进

- 补 `@Scheduled` 每日采集或外部调度（如 Quartz / XXL-Job），并把采集失败告警纳入运维。
- 把国家数据共享平台拆为独立服务，使用消息队列或可靠 outbox + 投递确认；补齐重放、死信与幂等键。
- 用 Redis / 数据库持久化会话，增加刷新 token、设备绑定与更细的角色权限。
- 将 AI 替换为 Spring AI + 向量库，保留引用、拒答、置信度与人工复核边界。
- 对象存储替代本地 `uploads`，增加病毒扫描、生命周期与访问控制。
- 补 Android 真机验收、弱网/离线队列与相机兼容性测试。
- 引入 HTTPS、备份恢复、监控指标（采集成功率、任务超期率、投递失败率）与审计检索。
